# Learning

The user primarily learns through implementation: idea → architecture → build → debug → iterate.

Strong preference for:
- practical projects
- implementation-led learning
- technical depth when it directly enables a project
- emerging AI systems
- connecting theory to working systems

# Execution strengths

- Rapid technical prototyping.
- Comfortable crossing stack boundaries.
- Strong decomposition into system components.
- Willingness to experiment.

# Execution risks

- Premature architecture.
- Learning a new technology instead of validating demand.
- Too many concurrent opportunity threads.
- Polishing systems before commercial evidence.

# Operating correction

During the founder window, learning should usually be downstream of the current commercial/system objective.
